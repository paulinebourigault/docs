Workflows let Certior own the orchestration of a sequential, policy-heavy pipeline. You define a list of stages — each with its own task, compliance preset, budget, and role — and Certior executes them in order, enforcing verification gates at each stage, passing upstream execution IDs forward automatically, and recording per-stage proof certificates in a single workflow object. When you're done, one `GET /api/v1/workflows/{id}/export` call returns the complete multi-stage audit package as a downloadable JSON file.

## When to Use Workflows vs Direct Tasks

Use workflows when:
- The flow is sequential and each stage must observe formal constraints before the next can start.
- You want Certior Studio operators to run and inspect the pipeline directly.
- You need a single object with unified per-stage audit evidence.

Keep orchestration outside Certior and use individual `POST /api/v1/tasks` calls when:
- Your application already has a coordinator with non-sequential branching, retries, or dynamic fan-out.
- You're embedding Certior as a verified execution gateway inside a larger system that manages its own control flow.

## POST /api/v1/workflows

Create and immediately start a multi-stage workflow. Certior executes all stages sequentially and stops on the first failure.

**Requires authentication. Users with `viewer` role cannot create workflows.** Returns `201 Created`.

### Request Body

<ParamField body="name" type="string" required>
  Human-readable name for the workflow. Maximum 160 characters.
</ParamField>

<ParamField body="description" type="string">
  Optional description for display in Certior Studio. Maximum 400 characters.
</ParamField>

<ParamField body="stages" type="array of objects" required>
  Ordered list of stage definitions. Minimum 1, maximum 12 stages. Each stage executes a separate verified task.

  <Expandable title="Stage fields">
    <ParamField body="id" type="string">
      Optional stable identifier for this stage. Used to reference the stage in `upstream_stage_ids` of later stages. Certior assigns a UUID if omitted.
    </ParamField>

    <ParamField body="name" type="string" required>
      Display name for this stage. Maximum 120 characters.
    </ParamField>

    <ParamField body="task" type="string" required>
      Natural-language task description for the agent at this stage.
    </ParamField>

    <ParamField body="compliance_policy" type="string" default="default">
      Compliance preset for this stage: `hipaa`, `sox`, `legal_privilege`, or `default`. Each stage can use a different policy.
    </ParamField>

    <ParamField body="budget_cents" type="integer" default="1500">
      Spend budget for this stage in US cents. Minimum `100`, maximum `1,000,000`.
    </ParamField>

    <ParamField body="stage_role" type="string" default="worker">
      Role of this stage in the pipeline. Examples: `intake`, `reviewer`, `release`, `worker`. `release`-role stages require at least one prior stage to have completed, enforcing the review-before-release constraint.
    </ParamField>

    <ParamField body="provider" type="string">
      LLM provider override for this stage: `anthropic` or `openai`.
    </ParamField>

    <ParamField body="model" type="string">
      Model override for this stage, e.g. `"gpt-4o"`.
    </ParamField>

    <ParamField body="api_key" type="string">
      Per-stage provider API key. Used only for this stage; not persisted to the execution record.
    </ParamField>

    <ParamField body="permissions" type="array of strings">
      Permissions to request for this stage. Intersected with the stage's compliance policy ceiling.
    </ParamField>

    <ParamField body="upstream_stage_ids" type="array of strings">
      Stage IDs that must complete before this stage can run. When omitted, Certior automatically chains the previous stage's execution ID.
    </ParamField>
  </Expandable>
</ParamField>

## GET /api/v1/workflows

List workflows for the authenticated user, newest first.

**Requires authentication.** Returns `200 OK` with a JSON array.

### Query Parameters

<ParamField query="status" type="string">
  Filter by workflow status: `pending`, `running`, `completed`, `failed`, `cancelled`.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Maximum number of results. Minimum `1`, maximum `100`.
</ParamField>

---

## GET /api/v1/workflows/{id}

Retrieve the current state of a single workflow, including per-stage status and execution IDs.

**Requires authentication.** Returns `200 OK`. Returns `404` if the workflow doesn't exist or belongs to a different user.

### Path Parameters

<ParamField path="workflow_id" type="string" required>
  The UUID of the workflow.
</ParamField>

---

## DELETE /api/v1/workflows/{id}

Cancel a running workflow. All pending and running stages are moved to `cancelled`. Stages that have already completed are not affected.

**Requires authentication.** Returns `200 OK` on success, `409 Conflict` if the workflow has already reached a terminal state (`completed`, `failed`, or `cancelled`).

```json
{
  "workflow_id": "wf-3a4b5c6d-...",
  "status": "cancelled"
}
```

---

## GET /api/v1/workflows/{id}/export

Export the complete multi-stage audit package as a downloadable JSON file (`Content-Disposition: attachment`). The package includes the workflow record, each stage's execution payload, and the full compliance package for every completed stage.

**Requires authentication.** Returns `200 OK`.

<ResponseField name="workflow" type="object">
  The full workflow record (same structure as `GET /api/v1/workflows/{id}`).
</ResponseField>

<ResponseField name="exported_at" type="number">
  Unix timestamp of when this export was generated.
</ResponseField>

<ResponseField name="stages" type="array of objects">
  Per-stage export records.

  <Expandable title="Stage export fields">
    <ResponseField name="stage" type="object">
      The stage record with status, execution ID, and output summary.
    </ResponseField>

    <ResponseField name="execution" type="object">
      The full execution record for this stage, if available.
    </ResponseField>

    <ResponseField name="compliance_package" type="object">
      The full compliance audit package for this stage's execution, if the stage completed successfully.
    </ResponseField>
  </Expandable>
</ResponseField>
